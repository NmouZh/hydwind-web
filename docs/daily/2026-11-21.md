## 反代改造 Agent · 21:43

### 改了什么

- 新增 `src/lib/api-client.ts`：`apiFetch` / `apiJson` 统一把页面 SSR 的请求发给
  `HYDWIND_API_ORIGIN`（默认 `http://127.0.0.1:8787`），转发 Cookie / Origin，
  用 `Astro.clientAddress` 生成 `X-Forwarded-For`，用请求 URL 生成
  `X-Forwarded-Host` / `Proto`，并拒绝 `/api/` 之外的路径。`ApiError` 带 status / body。
- 新增 `src/pages/api/[...path].ts` 的 `ALL` 反代：方法 / 查询串 / 流式 body 透传，
  `redirect: 'manual'`，逐条转发 `Set-Cookie`，保留 Location / Cache-Control /
  Content-Type，去掉 Content-Length / Content-Encoding 与逐跳头；后端不可达返回 502。
- `/gate`：不再调 `generateLoginCodes` / `readSession`，改为带 Cookie 调
  `GET /api/gate/codes`；401 → guest，其它失败 → error；码的 TTL 用响应里的 `ttlMs`。
  账号名从 `/api/auth/me` 补，拿不到时显示通用文案。
- `/people/`：改为 `GET /api/people?q=`，只渲染返回的 `PersonListItem`。
- `/people/[slug]`：改为 `GET /api/people/:slug` 取 person / biography / comments /
  viewer / canEdit；`source=static` 且有 `personId` 时仍用 `astro:content` 渲染
  Markdown 正文；评论删除按钮直接用后端的 `canDelete`。@提及映射额外拉一次
  `GET /api/people`，拉不到时退回静态人物 / 评论作者 / 当前人物。
- 删除旧 `/api/**` 路由与仅服务端使用的 lib（accounts、biographies、issues、
  login-codes、session、auth、plugin-auth、api-response、server-status、rate-limit、
  timing-safe、static-people、comments）及对应服务端测试。
- `people-list.ts` 去掉对 biographies.ts 的依赖，自带 `BiographyInput`，标题回退改用
  `person-page.ts` 的 `biographyTitle`。
- smoke 改成可选联通检查：后端不可达时明确跳过并 exit 0；可达时启动 standalone
  站点，经网站 `/api/health` 验证 200 + `ok:true`。
- `.env.example` 增加 `HYDWIND_API_ORIGIN` / `HOST` / `PORT`；README、`docs/backend-api.md`、
  `docs/security.md`、deploy 文档改为双服务 / 反代说明；CI 加 `feat/api-proxy` 触发，
  去掉 Playwright 安装（smoke 不再用 Chromium）。

### 为什么

后端已经拆到 hydwind-api，Web 里那份账号 / 传记 / 登录码实现成了重复维护的第二套逻辑。
改成 SSR + 反代后，业务规则、限流、权限判断只有后端一处，Web 只负责展示与传输。
